## Connected behavior

GNU Arm GCC still preprocesses each verified compilation unit with its original flags, macros and branch selection. A bounded lexer proves an exact standalone ordinary `"vfpcc"` token is in the third-colon GNU extended-asm clobber section, then writes only the seven-byte `"cc"   ` replacement to the temporary `.i` passed to zero-exit Clang declaration discovery. It leaves all other bytes, line markers, newline positions, source files and GCC build inputs intact. Unproved asm, prefixes, escapes, concatenations and other clobbers remain normal Clang failures. The versioned policy is now `gnu-asm-vfpcc-clobber-v2` in both plan fingerprint input and `engine_version`.

Round-1 review exposed unproved edits across raw physical line splices and repeated overlapping scans of nested asm. The helper now returns the entire input unchanged if it contains backslash-LF, backslash-CRLF or backslash-CR, including continued comments, directives and identifiers. Otherwise it consumes one shared forward token stream. A nested asm token inside a candidate leaves that candidate unchanged; later separate constructs can still be proved. The adversarial regression counts one tokenizer invocation and no more yielded tokens than input bytes for 1,000 nested levels. These changes keep helper work linear under the existing input limit.

Each `_discover` call memoizes successful path checks by exact root/candidate spelling and revalidates every cached path before the unit can be adopted. The adapter stages all function/declaration facts and duplicate translation-unit merges, checks the existing entry/deadline/closed-state rules, then commits the entire unit with `parsedUnits`. A late discovery failure publishes no prefix facts. Existing size, unit and time limits, DWARF lookup/address/CU rules, selection grammar and provider snapshot/binding checks remain authoritative.
