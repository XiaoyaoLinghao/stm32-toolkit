## Implemented behavior and boundaries

- Optional Schema 2/3 `generation.linkerFragment` names one project-relative UTF-8 GNU ld fragment. Omission preserves the historical model hash, generated bytes, managed-manifest bytes, and plan identity. A present value is read once as exact raw bytes; its SHA-256 and normalized sections become frozen model state, and the file remains user-owned and is never rewritten or listed as a managed file.
- The parser is a bounded hand-written tokenizer/recursive descent consumer, not a GNU linker-script interpreter. Limits: 64 KiB raw bytes, 32 sections, 64 statements per section, 256 total statements, 64 selectors per statement, 256 total selectors, 64-character names, 8,192 tokens, ALIGN a positive power of two at most 4096, and uint32 addresses. The whole input must be consumed; comments are stripped without being interpreted.
- Accepted output sections are custom writable-RAM `NOLOAD` sections only: `.name [address] (NOLOAD) : { . = ALIGN(n); *(...) KEEP(*(...)) } > REGION`. Selectors must be an exact custom section name or the trailing `.*` form and must stay inside the output section's own family. Duplicate/overlapping selectors and case-colliding output names are rejected.
- Reserved families are rejected casefolded: managed vector/text/rodata/data/bss, small-data (`.sdata`/`.sbss`), TLS (`.tdata`/`.tbss`), dynamic metadata (`.dynamic`/`.dynsym`/`.dynstr`/`.hash`), constructors/destructors, ARM unwind, heap/stack, `.stm32tk.abs.*`, and other standard metadata. `MEMORY`/`SECTIONS`, `INPUT`/`GROUP`/`INCLUDE`, `ENTRY`, `AT`, `PHDRS`, `INSERT`, `/DISCARD/`, symbol assignment, data emission, includes, and arbitrary wildcards are outside the subset.
- Region names resolve exactly against the canonical model map shared by fixed sections, linker rendering, ELF/MAP accounting, and build identity. Only writable regions are accepted; no region, capacity, or DMA reachability is inferred. Explicit addresses must satisfy `origin <= address < origin + length`.
- The bounded reader rejects absolute/drive/traversal/backslash paths, redirects at any path component (symlink/reparse), missing/directory/oversize/non-UTF-8 files, and collisions with sources, assembly sources, include paths, SVD, CubeMX IOC, managed manifest, native linker script, generated targets, `build/`, `artifacts/migration/`, or `.stm32-toolkit/generated-files.json`. A fragment cannot coexist with `generation.nativeLinkerScript`.
- Configure reads the fragment exactly once through the model, re-reads every hashed input, and cross-checks the fragment against the frozen digest so a race is refused rather than rendered. Validated sections render after existing fixed sections and before managed `.data`/`.bss`/`.heap`/`.stack`, in source order.
- PLAN binds the fragment path and exact SHA-256 into inputs and managed-manifest provenance (`linkerFragment = {path, sha256}`). Apply revalidates every digest, re-plans, refuses changed/deleted/redirected fragments and managed drift before its first write, and preserves the existing transaction/rollback behavior. The generated CMake gains a conditional `LINK_DEPENDS` on the merged `linker/stm32tk.ld` only when the fragment option is present.
- Build includes the fragment in the input snapshot and compares the recorded manifest provenance with the current model, so edits (including comments), deletion, path changes, option removal, and model changes invalidate old configuration/build evidence and are refused before any compiler spawn with structured remediation. Existing managed-linker/manifest digest checks remain mandatory.
- ELF validation inspects every nonempty section carrying a declared fragment name, not just allocated sections: a materialized declared section must be allocated `SHT_NOBITS` inside its declared writable region (exactly at an explicit address when given). A nonempty declared section with `SHF_ALLOC` cleared is refused as `fragmentNotAllocated`; all nonempty allocated sections must have disjoint VMA intervals, because MAP interval-union accounting alone cannot prove non-overlap.
- No new MCP tool, migration parameter, dependency, version, package, CI, automation, or global Skill was added. The existing `stm32_project_configure` (PLAN/APPLY) and CLI `project configure` routes are used unchanged.
- `NOLOAD` semantics are not changed: sections are never copied or zeroed, initialized C objects must not rely on initializers in these sections, and external RAM must already be usable before access. This slice does not change startup tables, programming eligibility, controller setup, or hardware behavior.

## Limitations and boundaries

- Supported subset only: custom writable-RAM `NOLOAD` output sections with the documented bounded grammar. There is no arbitrary GNU linker-script support, no MEMORY/SECTIONS ownership, no file-selection expressions, no symbol assignments, no includes/macros, and no initialization/copy/zero semantics.
- A selector may legitimately match no input, so a declared fragment section may produce no materialized output section; only nonempty evidence is validated.
- The generated merged linker remains managed; users reconfigure through the Toolkit. Direct CMake/Ninja use does not re-parse a changed fragment, and the conditional `LINK_DEPENDS` only ensures relinking after Toolkit regeneration.
- The installed/frozen 1.3.0 runtime lacks this source-only patch, as does v1.2.0. Unchanged tool inventory and input schema cannot prove a runtime contains it; a runtime built from this patch and a read-only PLAN with fragment evidence are required.
- This is offline source acceptance evidence. Packaging, installation, IDE/VS Code acceptance, release qualification, and hardware behavior are separate layers and are not claimed.
- No original-project access, hardware operation, installed-runtime change, global Skill change, frozen release-asset change, network/remote action, PR mutation, tag, package, or installation occurred in this slice. No credentials were exposed or authentication settings changed.
- Four real-symlink cases remain platform-deferred to primary release qualification; mocked direct/parent reparse tests passed.
