## Accepted behavior

Optional Schema2/3 `generation.linkerFragment` names a project-relative, user-owned UTF-8 fragment. The model reads bounded raw bytes, validates a limited grammar against the canonical base-plus-extra memory map, and freezes normalized sections plus the exact raw-byte SHA256. Configure renders these sections into the managed linker; it never rewrites or claims ownership of the fragment. A raw GNU `INCLUDE` is not emitted, so working-directory-dependent parsing and untracked secondary files cannot alter the generated layout.

The initial subset contains custom writable-RAM `NOLOAD` output sections, optional uint32 addresses, bounded power-of-two ALIGN, selectors confined to their own section family and KEEP. File size, sections, statements, selectors, tokens and names are bounded. Full input consumption, reserved families, duplicates/overlaps, region access/ranges, portable paths, missing/nonregular files, reparse components and generated/input ownership collisions are checked. Arbitrary expressions, symbol assignments, data emission, MEMORY/SECTIONS wrappers, external input/include commands and managed section families are refused. A native linker script cannot be combined with this route.

Sections render after fixed sections and before managed data/bss. Actual ELF checks require every nonempty materialized fragment section to be allocated NOBITS, fit its selected region and honor its explicit address. All nonempty allocated ELF intervals must be disjoint for fragment projects. MAP capacity accounting consumes the same canonical map; union accounting is not substituted for non-overlap proof. A selector matching no input may legitimately produce no output section. This does not initialize external RAM or copy/zero custom sections: initialized C objects must not rely on initializers in these NOLOAD regions.

Raw fragment path/bytes bind model identity, configure inputs, managed-manifest provenance and build snapshots. Edits, deletion, path changes, missing provenance and removal of the manifest option refuse stale builds before compiler spawn. PLAN/APPLY revalidation and transactional refusal remain intact. The supported repair is configure PLAN/APPLY, followed by a clean rebuild when required; no manual generated-files digest editing. Conditional CMake LINK_DEPENDS targets the merged linker, and real relinking after regeneration was verified. Direct CMake/Ninja does not parse a changed fragment: Toolkit configure must run first. Omitted options retain historical model hashes, managed-manifest bytes and generated bytes.

VS Code guide and migrate-keil skill document actual existing CLI/MCP calls, full PLAN/APPLY fields, earlier schema/path errors versus fragment-layer diagnostics, deleted-input versus provenance rules, and the exact project binding on both calls. The unchanged tool inventory/schema and a version string alone cannot prove patch availability; use a verified patched runtime and a read-only configure PLAN.
