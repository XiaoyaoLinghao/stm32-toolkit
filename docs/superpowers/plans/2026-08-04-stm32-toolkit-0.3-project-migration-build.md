# STM32 Toolkit 0.3 Project Migration and Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the 0.2 foundation into a deterministic, auditable path from one real Keil project to a reproducible GCC/CMake build with firmware identity.

**Architecture:** Introduce a schema-neutral immutable project model, read-only Keil inspection, digest-guarded conversion plans, managed-file generation, and a bounded CMake build runner. CLI/MCP tools adapt these modules; Skills only select workflows and request authorization.

**Tech Stack:** Python 3.10+, jsonschema, ElementTree, dataclasses, Jinja2, CMake 3.22+, Ninja, ARM GNU Toolchain, pytest.

## Global Constraints

- Current real Keil project only; no batch migration or all-chip rule database.
- Never write `.uvprojx` or combine compiler migration with framework conversion.
- Inspect/plan/dry-run are read-only; apply requires clean/recoverable Git state and unchanged input digests.
- Generated user files are not overwritten after drift.
- Every build records Git commit, ELF SHA-256, target, preset, time, and Toolkit version.
- TDD each behavior; full Python branch coverage remains at least 90%.
