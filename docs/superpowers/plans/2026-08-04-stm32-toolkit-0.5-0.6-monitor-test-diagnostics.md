# STM32 Toolkit 0.5–0.6 Monitor, Test, and Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a project-isolated real-time monitor, host/target test execution, and an evidence-driven AI diagnostic loop without changing the agreed monitor requirements.

**Architecture:** `stm32-monitor` is a same-version companion package that consumes the authenticated loopback Probe Service from 0.4; it never opens PyOCD or a probe directly. Persistent watch-group definitions are user-created and workspace-scoped, while samples, test artifacts, diagnostic sessions, and audit records live under the plugin data directory. All mutating hardware actions pass through the Probe Service policy and lease checks.

**Tech Stack:** Python 3.10+, FastAPI/uvicorn, Pydantic, SQLite in WAL mode plus bounded immutable export artifacts, TypeScript, Vite, ECharts, Vitest, Playwright, CMake/CTest, Unity/CMock, pytest.

## Global Constraints

- Never ship or auto-create named monitor groups; every group is explicitly created by the user in the UI or imported by the user.
- Bind HTTP/WebSocket servers to loopback only, use a random available port and per-launch token, and never log the token.
- Preserve project isolation using `workspaceId`, canonical project root, project fingerprint, and firmware identity on every stored or streamed record.
- Monitor reads may hold a shared read lease only where the selected backend proves that safe; flash and debug control always pre-empt or reject conflicting monitoring.
- Do not infer C types from byte size. Resolve symbols and types from ELF/DWARF and registers from the selected SVD.
- Sampling intervals exposed to users remain 100 ms–5 s; report measured rate, latency, dropped samples, and target halt impact rather than promising exact timing.
- No external CDN or internet dependency is allowed at runtime. Bundle all frontend assets.
- Never override browser globals such as `window.setInterval`.

## 0.5/0.6 Exit Criteria

- [ ] A user can create arbitrary monitor groups in the UI, observe typed variables/registers and history, and export evidence; a fresh project has no named presets.
- [ ] Monitor, test, and diagnostic data from two simultaneous projects remain isolated.
- [ ] Conflicting flash/debug/monitor operations are rejected or coordinated by leases with visible reasons and complete audit records.
- [ ] Host and target test artifacts are tied to source, project, toolchain, ELF, image CRC, probe, and target identities.
- [ ] A fake end-to-end AI diagnostic loop passes in CI, and at least one real-board smoke run is archived for each supported transport before that transport is documented as supported.
