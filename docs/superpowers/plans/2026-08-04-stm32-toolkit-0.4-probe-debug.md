# STM32 Toolkit 0.4 Probe and Debug Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the 0.3 Toolkit one safe hardware-access path for probe leases, flashing, Cortex-Debug handoff, typed runtime reads, sampling, registers, and Fault evidence.

**Architecture:** A loopback Probe Service is the only PyOCD session owner. MCP, Monitor, tests, and CLI use a versioned authenticated `ProbeClient`; a global registry arbitrates physical probes and a workspace state machine explicitly hands ownership to Cortex-Debug.

**Tech Stack:** Python 3.10+, PyOCD, pyelftools, cmsis-svd, aiohttp, jsonschema, pytest, FakeProbe.

## Global Constraints

- One physical probe has one owner; conflicts report workspace/session/PID and never steal ownership.
- Never kill unrelated PyOCD processes.
- Observation is attach/non-halting by default; halt/step/reset/flash requires the approved operation level.
- No Option Bytes, arbitrary writes, chip erase, or flash of stale/wrong-target firmware.
- Service binds `127.0.0.1`, uses a dynamic port and random token, and rejects incompatible protocol/Toolkit versions.
- All hardware evidence includes exact firmware identity and audit metadata.
- TDD behavior with FakeProbe; at least one real-board gate remains mandatory for 1.0.0.
