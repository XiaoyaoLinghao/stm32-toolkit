## M3a: explicit WFI return in the source/delivery core

Add an immutable bounded `wfiReturns=[{path,function}]` choice to analysis, preflight and independent delivery. Paths are exact portable project-relative C sources; names are exact ASCII C identifiers. Reject unknown keys/types, duplicate selections, escaping paths, excessive counts/lengths, unused or ambiguous selections. No selection changes no-choice serialized option/plan shapes except the intentional clearer diagnostic. Bind nonempty choices and source hashes into delivery planId/report/source-change previews; apply recomputes them. Reuse existing plan authorization.

Only one plain file-scope zero-argument `__asm void name(void)` or `name()` containing WFI alone, optional trailing semicolon and lexical comments, with no explicit return, can use this choice. Require actual lexical file scope and reject storage/prefix tokens, macro/directive ambiguity, multiple definitions, nested bodies, unknown/extra instructions or arguments. A line break after a storage token does not make a function plain. Do not broaden MSP/CPSID/CPSIE or unknown assembly. Existing explicit-return wrappers retain their current translation.

The selected function becomes ordinary non-naked C executing `__asm volatile ("wfi" ::: "memory");` and returning normally. Preserve name/prototype, comment content, BOM/newline convention and adjacent functions. Record this as requested source behavior, not binary equivalence. Without selection, give path/function and a concrete normal-return choice, or explain that intentional fall-through needs a project-owned source port. Keil AXF or disassembly is not a prerequisite. Duplicate/unused choices must not silently succeed.

Allowed core files: migration/source_intent.py (if needed), model.py, rules.py, planner.py, delivery.py and preflight.py; focused test_wfi_return_intent.py and test_retest_diagnostics.py. Do not modify public CLI/MCP/workflow adapters in M3a. Preserve their no-option behavior. Core tests cover malformed/mixed/unused choices, duplicate definitions, conditional/macro/nested ambiguity, source/option/destination drift, CRLF/comments and unchanged adjacent interrupt wrappers. Real ARM GCC test compiles the generated WFI function and checks its emitted WFI/normal return without an interrupt-disable instruction; this tests generated GCC output, not a required Keil baseline.

## M3b: public route and complete source preparation

After M3a acceptance, expose repeatable CLI `--wfi-return 'Common/common.c:WFI_SET'` and MCP `wfiReturns` on preflight/convert. Preserve the same choices on PLAN/APPLY and use exact public fields. Update context/remediation, skills and VS Code guide accordingly. Validate actual registered MCP schema/calls and CLI parsing, not merely strings.

Use the existing project normalize-source-comments helper; do not build a second transcoder. Explain original source -> reviewed per-file comment copies -> complete separate prepared tree -> independent GCC output -> normal GCC build/flash. The normalizer output is a partial file set, not a complete buildable project. The prepared tree retains unselected source, headers, startup and licenses; overlay only the reviewed converted files and recheck hashes. Keep invalid-byte replacement opt-in and per-file reviewed confirmation. Original and prepared input trees remain unchanged by migration. Remove obsolete Git and binary-baseline prerequisites, reduce the main migration skill to the operational route and move conditional detail to linked references.

The combined regression fixture includes GBK comments and a header, ARMCC startup, absolute placement, group include, explicit external RAM, WFI return intent and no Git. Demonstrate real GCC output-only rebuild with original/prepared trees unavailable, then the normal managed fake-flash/readback route after integration with content identity. Global reusable normalizer synchronization is a separate backed-up action under the user's earlier project/global reuse authorization, after review; no unrelated settings.
