## Supported behavior

Extend the existing token-aware source rules, not a global textual replacement. Preserve UTF-8 BOM, CRLF/LF and comments/string/character/raw-string/preprocessor bodies. Work on included C sources only for new function/declaration rules; unsupported C++ constructs retain explicit blockers. Read-only preflight and PLAN expose exact proposed rule IDs, patches and fixed-section evidence. Existing APPLY authorization, Git baseline, fresh replan and transactional rollback remain mandatory.

1. Recognize only complete, plain `__asm void` function definitions with exactly one of WFI; CPSID I; CPSIE I; MSR MSP,R0 followed by BX LR (or BX R14). No additional instruction, label, directive, call, branch, conditional assembly, macro body or extra statements. Preserve the function name/prototype and comments; reject uncertain prototypes. Zero-argument forms for the first three, a single scalar parameter for MSP. Convert to GNU naked basic asm with a single literal instruction string and no C statements or extended asm operands. This deliberately retains the original no-prologue behavior and avoids the unsafe ordinary C wrapper around __set_MSP. Verify all four using real ARM GCC at O0/Og/O2 and objdump: expected instruction then BX LR, no stack access or compiler prologue before return. Compiler-added unreachable padding after BX is not execution. Do not claim CMSIS header availability or invent one.

2. Translate bounded `__align(n)` on supported plain object declarations into `__attribute__((aligned(n)))`. n is a positive power of two up to an explicit sane bound (4096); integers/fully resolved bounded macros allowed. Invalid/unknown alignment remains a blocker. Do not silently carry unrecognized __align into supposedly ready GNU source.

3. Extend existing absolute placement to a single, uninitialized scalar or fixed-size array declaration, prefix or suffix `__attribute__((at(EXPR)))`, and __at(EXPR). Retain qualifiers, symbol, type and dimensions. Reject pointers, functions, initializers, multiple declarators, conflicting attributes and uncertain grammar. Resolve EXPR with a bounded integer evaluator (no eval/exec), supporting decimal/hex integer literals with standard unsigned/long suffixes, parentheses, identifiers and a documented small operator set including +. Enforce uint32 addresses, bounded shifts/recursion/token count and nonnegative size/alignment. No float, function macros, sizeof, casts, undefined identifiers, cycles, ambiguity, overflow or division guessing. Duplicate placements keep existing blocking behavior and no partial placement rewrite per file.

4. Resolve object-like integer macros from explicit target defines and contained literal quoted includes through source directory and merged include paths. Support a bounded include chain and ordinary unambiguous include guards; do not evaluate arbitrary preprocessor conditionals. A used macro with conditional, conflicting, redefined or undef evidence is unsupported, even if one guessed value would work. Bind all dependency bytes (including ignored headers) to plan inputs and include-resolution evidence to fresh PLAN/APPLY revalidation; newly shadowing headers must not silently change an approved result. Fail closed on redirects, escapes, unavailable files, ambiguous include resolution and limits. No header/source is rewritten merely to supply a macro. Unneeded library/system includes do not cause unrelated formerly convertible source to fail: build resolution only for rules needing symbolic values and conservatively report unavailable evidence for requested symbols.

5. Recognize only exact standalone `#pragma import(__use_no_semihosting)` (optional preserved trailing comment, no continuation or extra tokens) and remove that directive for GCC. Unknown imports/pragmas keep their blockers. Record a distinct rule ID and an explicit build.newlibSpecs=["nosys.specs"] in the proposal. Add this optional bounded schema/model field and generate it in link options for managed linker generation; preserve old absent-field output and native linker defaults, avoid duplicate specs. Do not add nano.specs implicitly, remove user I/O stubs or claim runtime I/O equivalence. This small model/template change is necessary for the selected pragma behavior, not a generic linker customization API.

Fixed placements remain constrained by explicitly declared memory regions. An address outside every region must be reported as needing user-supplied memory definition, not invented external SRAM size. This slice does not add memory.extraRegions, linkerFragment, alter float ABI, transcode GBK or loosen artifact range checks. Report limits clearly; successful syntax conversion does not prove behavior-equivalent firmware.

## Implementation clarifications from draft review

Known alignment and absolute-address attributes may compose on the same otherwise supported object. Reject extern/typedef/zero-size or uncertain storage declarations. New MSP wrappers use known 32-bit integer parameter forms; an unknown typedef is not proof of a safe scalar calling convention. The four asm patterns all require the explicit BX return from the design; preserve original newline convention and comment text, including comments around prototypes and trailing pragma comments.

Macro replacement must preserve C token precedence, not evaluate each macro separately and substitute its integer value. The bounded decimal/hex grammar may reject leading-zero octal-looking forms and type-dependent operators such as unary complement instead of guessing C integer types. Limits must fail as diagnostics before expensive parsing/list materialization. Conditional includes carry conditional provenance to their definitions; stripping an ordinary include guard requires structural evidence and cannot assume an already-defined guard is absent. Quoted nested include paths are resolved component-wise with containment and redirect checks.

Preflight adds `analysis.sourceChanges`, a concise list of proposed source patch paths, rule IDs and before/after digests. PLAN remains the full diff authority and APPLY remains the only authorized migration write. This is an additive output field, not a new tool, input parameter, permission or readiness gate. VS Code guidance must use the actual serialized names implemented and tested.

The optional nonempty newlib specs must also participate in `generation/managed_files.py` model identity, so a changed link option requires fresh configuration. This minimal identity wiring is allowed scope alongside configure.py. Preserve the historical model identity payload when the option is absent/empty; test both identity change and absent-field compatibility.
