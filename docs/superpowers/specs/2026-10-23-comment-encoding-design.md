## Contract

Create `skills/normalize-source-comments/SKILL.md` plus a self-contained standard-library Python helper and proportionate references only when necessary. Keep normal discovery enabled. No hooks, auto-running content, provider configuration, new MCP tools, version bump, installer/release changes or third-party dependencies. The canonical project skill is shareable via the existing plugin skill convention; the primary installs byte-identical approved content globally afterwards, under the user's explicitly approved scope.

The skill separates inspect/preview from copying reviewed converted files. Default is read-only preview. It must never re-encode a whole source file blindly or assume all non-ASCII bytes are comments. Inputs are explicit project-root-relative C/C++ source/header paths with an explicit per-file charset (`utf-8`, `gb2312`, `gbk`, `gb18030`, or explicitly `cp1252`). Different files can have different declared charsets. No automatic charset guessing/fallback; decoding successfully does not prove the intended human text. Report private-use/mixed/invalid bytes as review issues. Assembly, UTF-16/32, binaries and arbitrary text formats are outside this first helper; leave them untouched with a clear diagnostic.

For a supported file, strictly decode the selected codec, prove exact byte round-trip, identify actual C/C++ comment spans, convert only comment text to UTF-8 and preserve all bytes outside those spans, comment delimiters, CR/LF/CRLF sequence, final-newline state and any existing UTF-8 BOM. No BOM is added. The resulting entire file must be valid UTF-8; non-ASCII code/string/character/header-name bytes in a legacy-encoded file block conversion instead of silently changing literal runtime bytes. UTF-8 files are unchanged and idempotent. Block undecodable input with path, byte offset and line; do not replace/ignore invalid sequences or invent the lost comment text.

Lexical correctness matters: distinguish normal quoted strings/chars and escapes, `//` versus `/* */`, comment-looking literal content, preprocessing header names, and backslash-newline continuations including split comment delimiters. A practical implementation can build a phase-2 logical character view with source-span mappings, but must retain original physical line endings. Raw C++ strings must either be parsed correctly or rejected explicitly with no write; unknown or unterminated lexical constructs are blockers. Trigraph constructs and a DBCS trail-0x5c at physical line end require explicit conservative handling/blocking, not an ASCII regex that misidentifies their roles. GCC also accepts a backslash followed by horizontal whitespace before the physical newline as a continuation; either implement that with correct source mapping or conservatively block it explicitly, never misclassify its following line as code/comments. Test this case. Do not claim to be a full C compiler. Primary checked the GCC initial-processing reference: https://gcc.gnu.org/onlinedocs/cpp/Initial-processing.html .

Preview outputs portable per-file findings, source charset, before/after raw SHA-256 and sizes, outside-comment byte digest, newline/BOM evidence, human-readable diffs, blockers and a canonical plan ID. The plan binds selected paths/codecs/input bytes and proposed output. Store previews outside the original source tree. No plan field or diagnostic is authorization to alter original files.

An explicit copy invocation accepts a reviewed plan and exact expected plan ID, re-reads and validates every input, re-derives the conversion and proves unchanged plan/output hashes before writing. Any blocker, modified input, tampered plan, invalid path, redirected/reparse path, destination collision or destination nested inside/containing the source root fails clearly. Copy only selected relative files into a new external output directory, preserving layout; say this is a set of converted file copies, not a complete migrated/buildable project. Never overwrite existing output or originals. Bound file count and bytes; no unchecked recursive scan. I/O failure cannot report success; keep any owned incomplete staging clearly marked or safely clean only newly created owned staging. A machine-readable final manifest proves output hashes and originals unchanged.

The skill's guidance gives exact PowerShell commands and parameter names from the actual helper, shows per-file charset selection, preview review, authorized copy, byte verification, then Toolkit `stm32_keil_inspect` -> `stm32_keil_preflight` on the deliberately prepared project copy. Original project replacement/in-place edit is a separate explicit user decision; no automatic Git init/commit/migration apply/build/flash. If all encoding blockers disappear, startup, scoped options, scatter/memory, Git/apply and baseline blockers remain independent. This route does not promise generic charset support or runtime string/ABI equivalence.
