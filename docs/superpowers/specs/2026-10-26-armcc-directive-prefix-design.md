## Problem and contract

Read-only audit `71da2a45-6316-42b9-acd0-ff308d1f0e33` found that both migration/rules.py and keil/armcc_scan.py use raw characters before `#` to decide whether it starts a directive. A preceding block comment may therefore hide a real ARMCC pragma from both scanners. This is a source-derived hypothesis until the first native regression runs. GCC's [initial processing documentation](https://gcc.gnu.org/onlinedocs/cpp/Initial-processing.html) confirms that comments are replaced with whitespace before directives are interpreted; a comment prefix is not an ordinary code token.

The single supported no-semihosting pragma should retain its existing exact rewrite and nosys.specs behavior when the directive is preceded only by whitespace and real block-comment trivia. Preserve all comment/string bytes, BOM and original newline sequences; preserve source line/column evidence. Unsupported ARMCC import/arm/optimization pragma forms must remain blockers, including after comment trivia. Do not silently accept a real directive merely because it has a comment prefix.

Recognize lexical context, not a broad regular-expression removal of comments. Comment contents, strings, character/C++ raw strings, continued line comments, macro bodies and ordinary mid-code `#` must not become rewrite targets. Existing backslash continuation boundaries remain conservative; this is not a complete preprocessor or macro evaluator. Reconcile inspection findings with migration rule results through existing contracts so a supported rewrite is not accidentally blocked by its leading comment, while unknown/capped evidence does not grant a bypass. Avoid an unconditional pragma suppression or filename/path exceptions.
