## 2. 已观察的问题

证据均来自发布标签源码；本轮没有把静态审查当作浏览器或实机测试。

1. `ui/src/styles.css` 的 `.monitor-shell>header,.monitor-shell>footer,.monitor-shell>section` 全部跨满网格，虽声明两列，主要内容仍逐段堆叠。
2. `ui/src/app.tsx` 依次平铺身份、探针、目录、分组、采样、数值表、图表、缩放、状态、提示、历史和导出；主要观测内容被配置表单推后。
3. `app.tsx` 和各面板使用大量英文可见文本、无障碍名称和原始状态枚举。错误主要直接显示 `code: message`。
4. `components/LiveChart.tsx` 图高固定为 280px，当前没有随容器变化的 resize 处理；工作台布局调整时必须处理图表重排。
5. `components/StatusStrip.tsx` 数值使用全局 block output，延迟直接显示纳秒，丢弃统计以英文平铺；不利于快速扫读。
6. `components/HistoryPanel.tsx` 输入使用 datetime-local，但按 UTC 解释，界面未显式标注 UTC；初始范围来自 0ns，会显示 1970 年。应在展示层明确时间语义。
7. `state/reducer.ts` 将一般 `request.failed` 也写入 `blockingError`，`app.tsx` 因而只显示整页错误；该行为已有测试固化。错误恢复需要单独的状态契约变更，不能当作 CSS 修改顺带修补。

## 3. 四个可运行用户场景

### S1：打开并开始观测

打开当前 Monitor 服务授权页面 → 中文引导说明连接状况 → 用户明确选择/连接探针 → 选择已有观测组 → 开始采样 → 同屏看到采样状态、波形和最新数值。

连接动作仍通过既有 controller/API 执行；“连接成功”不等于“正在采样”。无探针、无观测组、连接失败均有对应解释和可执行下一步。

### S2：配置观测对象并持续查看

左侧搜索变量/寄存器 → 添加到观测组草稿 → 检查参数并保存 → 主区选取曲线、查看值、缩放 → 暂停/继续/停止采样。

草稿和已保存组有清晰区别；切换页面不能丢失草稿，不能另建采样实例或重复订阅。“暂停采样”与“停止采样”仍是既有后端语义，不包装为仅冻结画面。

### S3：回看与导出

进入“历史记录” → 选择明确标有 UTC 的起止时间 → 查询/翻页 → 以已提交查询范围预填导出范围，或手动选择独立范围 → 生成 CSV/JSONL → 查看生成状态并下载。

尚未查询时给出选择范围的空状态，不展示 1970 年为业务默认时间；不自动查询全部历史。不改变纳秒时间、游标或导出协议。

导出范围契约：尚未编辑或与上次查询同步时，新的已提交查询更新导出输入；用户手动修改后，后续查询不得覆盖草稿，显示“查询范围已更新，保留当前导出范围”及“使用查询范围”入口。没有历史查询时仍允许手工指定范围独立导出。创建导出以屏幕中已校验的导出草稿为准；已创建任务显示其提交时的范围，不随输入或历史查询改变而改写。切页保留这些 UI 草稿。验证空、倒序、手改后查询、主动同步及任务范围保留。

### S4：识别中断与诊断边界

采样时出现断连、固件身份变化、受阻或请求失败 → 中文状态和错误说明定位问题 → 展开原始错误码/消息。仍能显示工作台的状态提供原有操作；触发 blockingError 的请求保留整页失败语义，以中文说明当前操作未完成及如何通过原入口重新打开授权页面，不增加未经定义的“自动恢复”。

断流后不得仍显示“正常采样”，旧数值明确标识为非最新；不得自动抢占探针、复位、重烧或绕过身份/租约校验。

后续 MONITOR-UI-02 再设计“普通操作错误就地显示、可安全重试、致命错误阻断”的完整契约，冻结错误分类、清除时机和请求生命周期后单独批准实施。UI-01 不宣称已经解决该状态恢复缺陷。

## 5. 信息架构与视觉方向

用户已确认默认浅色专业工作台。

- 顶栏：STM32 Monitor / 中文“监视器”名称、项目、连接状态、设备入口；较长 ELF 路径和身份 ID 放在“连接与固件详情”。
- 主导航：实时监视、历史记录。导出跟随历史查询范围展示，不独占一整页空表单。
- 实时页：左侧约 280–320px 的观测组与变量列表，主区为波形，下方为紧凑数值表。选组与采样控制靠近波形。
- 配置入口：变量目录、组编辑、设备详情按需展开；不让配置表单长期占据主画布。变更布局不丢失组件草稿。
- 底部状态：实际采样率、延迟、四类丢弃计数。按重要性突出异常，但同时保留文字说明，不仅依靠颜色。
- 样式：中文 UI 系统字体栈（Segoe UI、Microsoft YaHei UI、Microsoft YaHei、sans-serif）；变量/寄存器/数值用可用的系统等宽字体，数值采用等宽数字。无网络字体。
- 视觉建议：浅灰背景 `#F4F6F8`、白色内容面 `#FFFFFF`、主文本 `#182230`、次文本 `#536174`、边界 `#DCE2E9`、主操作蓝 `#2563EB`；只为状态与不同曲线使用额外颜色。
- 基础正文 14px，辅助文字不小于 12px，标题 16–20px；控件高度约 34px，4/8px 间距体系，8px 面板圆角，少量分隔线，避免每个单元格重边框。
- 桌面 1440×900 与 1366×768：开始采样、采样状态、图表和至少 3 行最新值在首屏。1024px 下压缩侧栏，768px 下重排为单列，320px 可访问所有操作且不发生页面级横向溢出；数值表允许局部横向滚动。
- 键盘 focus 清晰；文字对比度按 WCAG AA；200% 缩放和长中文错误不裁切；减少动画偏好生效。

## 6. 中文化契约

1. `index.html` 使用 `lang="zh-CN"`；页面标题、导航、按钮、标签、占位、空状态、loading、对话框、状态、校验提示、图表 UI、aria-label 都属于中文覆盖范围。
   `bootstrap.ts` 的启动/令牌失败文案也纳入翻译，认证、路径、fragment token 的读取与清除逻辑保持不变。
2. 文案以本地 typed 字典/格式化函数为单一来源，使用项目现有 TS 能力；不新增 i18n 运行库。文案 key 不写入 API 或持久化模型。
3. 品牌/技术名和用户数据保持原样，例如 STM32、SWD、CSV、JSON、变量表达式、错误码、ELF 路径。不得翻译识别符而导致请求变化。
4. 以错误 code 映射中文标题与可执行说明。未知 code 使用“操作未完成，请查看详细信息”；原始 code/message 在详情中保留，不猜测失败原因、不用字符串替换重写原始消息。
   reducer 发出的 notice 仍不改模型：有稳定 code 时按 code 映射；没有 code 的已知常量由 NoticeRegion 的 presentation adapter 精确匹配成中文摘要，原文仅留诊断详情。未知 notice 使用“监视状态已变化，请查看详情”，不展示猜测的原因。`MONITOR_IMPORT_INVALID` 在 GroupPanel 按错误码翻译，`state/group-transfer.ts` 保持不变。原始诊断展开后允许保留英文。
5. 状态映射覆盖基线已有枚举并提供未知状态回退，例如 IDLE→未采样、RUNNING→采样中、PAUSED→已暂停、PAUSED_BLOCKED→采样受阻、STOPPING→正在停止。操作是否可用仍由既有契约决定，不借翻译修订状态机。
6. 实际采样率明确标为“实际”；延迟可按量级展示 ms/μs/ns，原始 bigint 纳秒在详情中可见，禁止经不安全 Number 转换丢失精度。
7. 历史仍按 UTC 解释，字段明确标 UTC；内部时间保留 bigint ns，不能把 UTC 与本地时间静默互换。

## 7. 冻结的状态、生命周期与依赖方向

| 状态/责任 | 唯一来源 | UI 允许做什么 |
|---|---|---|
| 探针/身份/采样状态 | 既有 API status 与 controller/reducer | 翻译和分层展示；不推断硬件成功 |
| WebSocket 生命周期 | 既有 controller 单实例 | 导航不创建第二 controller，不触发第二 loadInitial |
| 组、组草稿、选中序列、历史查询、导出结果 | 既有 reducer/model/selectors | 重用现有 action；UI 隐藏/展开不丢失状态 |
| 纯展示：当前页、抽屉展开 | 独立 UI 局部状态 | 默认实时页，不持久化至后端 |
| 图表数据和 zoom | 既有 selectors 与 zoom 模型 | 改视觉、标签、尺寸；resize 不重建订阅或清空数据 |
| 中文文案/人类可读格式 | 本地 presentation 字典与 formatter | 不修改传输/存储模型 |

依赖方向：组件 → presentation 字典/formatter 与既有 controller/selectors → API/codec；API、协议与后端不得反向依赖语言/主题。

页面切换保持一个连接。图表容器使用 ResizeObserver 通知 ECharts resize，卸载时解绑 observer 并 dispose；隐藏页恢复时重算尺寸。不会将滚动或每次采样变成反复初始化。

对话框应有名称、初始焦点、Esc 关闭及返回触发器焦点；表单、采样状态与通知在中文化后仍可供屏幕阅读器使用。采样每点变化不触发全屏读屏公告。

## 8. 验收边界

- S1–S4 均有可操作路径；所有既有用户功能都能从新布局到达，不能只制作静态好看首页。
- 可见产品文案与无障碍名称默认中文，机器/用户数据保留原文；已知与未知错误均可查看原始诊断。
- 相同用户动作调用相同 API 语义；组件重排不重复订阅、不丢草稿、不清空曲线、不改变时间精度。
- 主工作区在指定桌面尺寸通过浏览器截图检查；空/加载/错误/暂停/受阻状态也通过检查，不只验有数据截图。
- UI 类型检查、lint、现有回归、受影响的交互/a11y 和构建校验通过。风险新增测试针对契约和用户路径，不为纯间距/颜色写镜像测试。
- 生成的 ui_dist 与前端源一致；完整 release 矩阵和实机吞吐量不属于此切片。
- 设计预览中的图形和数据均为示例，不属于已实现产品或硬件证据。
