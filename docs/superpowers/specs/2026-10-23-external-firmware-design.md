## Image semantics and limits

Explicit flash allowlists are declarations reviewed by the user, not independently established hardware facts. This initial scope supports STM32 internal application Flash addresses only, 0x08000000 <= start < end <= 0x10000000. Reject RAM, system/option/OTP and external flash regions. 1..32 regions, positive lengths, exact ints (not bool), uint32 bounded, sorted canonical, no overlaps/duplicates. Do not infer chip capacity or physical target facts. Each programmed segment must fit entirely in one declared region; no silent dropping, wrapping, overlap (even identical duplicate bytes), or gap filling. If future native target maps are narrower, the entire image must be rejected before the first write.

Source bytes are bounded to64MiB; normalized ELF must also fit64MiB, no more than1024 segments and bounded record/JSON input. Zero-data images reject. No new dependencies, external converters or subprocess parsers.

ELF/AXF: strict ELF32 little-endian EM_ARM ET_EXEC. Read every nonempty PT_LOAD physical-address payload. Validate file offset/size bounds, filesz<=memsz, uint32 address ranges, no overlaps and nonempty data. Reject malformed/truncated/wrong-architecture/dynamic/unsupported images. BSS-only memory is not programmed. Do not claim MCU identity or runtime correctness from the ELF header.

Intel HEX: ASCII strict record lengths/checksums/EOF ordering, types00/01/02/03/04/05 only with exact metadata lengths/offsets; reject missing/repeated EOF, trailing records, overlap, uint32 wrap and unknown types. Handle extended segment/linear addresses. Start-address metadata is reported when present and never used to guess base/target or reset behavior. Avoid filling sparse gaps. BIN: explicit uint32 baseAddress required, and baseAddress is forbidden for non-BIN. No default boot-address inference.

Normalize selected payloads deterministically into a minimal ARM ELF32 image using PT_LOAD only, with matching physical/virtual flash addresses and exact payload bytes. Imported original ELF debug/symbol metadata remains only in preserved source bytes; normalized image is for programming, not debugging. No vendor code transformation or new startup synthesis occurs here. Source SHA and normalized image SHA are distinct public fields. Verify the normalized PT_LOAD byte map independently in tests and primary review.
