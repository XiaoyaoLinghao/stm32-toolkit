## Four caller scenarios

1. Resume an acceptance attempt or diagnostic investigation from authenticated
   persisted state. Valid retries preserve identity; malformed, contradictory
   or stale state cannot authorize a transition or rewrite accepted evidence.
2. Create, migrate, configure or regenerate a project. A valid operation commits
   its managed outputs; input drift, tool failure or invalid authorization
   preserves user files and leaves a defined rollback/consumption result.
3. Prepare and execute a bounded target/test operation through existing software
   provider seams. Refusal happens before prohibited dispatch, and success,
   cancellation and failure settle process ownership, leases and publication.
4. Ingest, load, analyze, query and stream recorded observations. Public wire
   validation, provenance, pagination and lifecycle failures preserve authority,
   expose the specified error family, and do not leave partial derived state.

These are software contract tests. They do not create physical evidence. No new
hardware scenario, feature, engine, schema, adapter, diagnostic framework,
