## Public behavior

- Existing standalone helper `preview` gains `--replace-invalid-with '?'`, the sole supported replacement value. Omitted means strict historical behavior. Charset remains explicit per selected file, with no guessing or fallback.
- Opted-in mode can replace undecodable non-ASCII bytes and existing disallowed private-use/C1-control/U+FFFD/noncharacter code points **only in proven C/C++ comment content**, including explicitly declared UTF-8. Valid ordinary comment text still converts normally. No original file is written.
- Preserve every byte outside comments, ASCII punctuation and delimiters, all newline bytes and final-newline state, BOM, and valid text not selected for replacement. No `errors=ignore` or blind whole-file replacement. Retain original byte mappings and round-trip evidence for decodable units; do not claim a strict source decode succeeded when it did not.
- Any error span that would consume ASCII syntax/newline bytes is blocked, never replaced as a unit. Invalid byte units must remain opaque to the lexer. Decode/recovery ambiguity, raw strings, trigraphs, unsupported continuation forms, incomplete constructs, non-comment invalid bytes and existing path/reparse/output bounds continue to block. A replacement must not create a lexical hazard (including trigraphs) or change comment recognition: re-validate derived output, outside-comment digest and idempotence.
- Preview binds the exact mode, replacement value, source/output hashes, and replacement records into planId. Each replacement record gives path, original physical byte offset/length/hex, line/column, reason and replacement. Report per-file counts and lossy status plus byte diff. Records are bounded; exceeding the loss-record limit blocks instead of silently omitting approval-relevant changes.
- Existing finding codes remain usable; diagnostics explain whether an explicit reviewed comment-only replacement preview is applicable. Do not assert comment-only eligibility without lexical proof, or automatically suggest a new charset.
- `copy` gains repeatable `--confirm-file '<relative path>'`. For a replacement plan, require exactly every file with actual lossy replacements, tied to the supplied exact planId. Reject missing, duplicate, unknown or non-lossy confirmations before creating output. Strict copies require no new confirmation. Confirmation is explicit review evidence, not authorization to mutate originals or permission for hardware.
- Copy re-reads and re-derives every input and every replacement, rejects stale/tampered plans and options, and preserves existing exclusive external output/incomplete marker/manifest behavior. Manifest records mode, confirmed files and losses without claiming migration completion.
- Version the helper/plan contract if necessary; old incompatible plans must fail with actionable re-preview guidance rather than silently changing their meaning. Toolkit/Monitor/plugin/release version remains unchanged.
