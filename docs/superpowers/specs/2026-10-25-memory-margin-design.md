## Public contract

Use the existing validated ELF/MAP interval-union accounting and explicit normalized model regions (including extraRegions). Do not change allocation/accounting, guess capacity, or relax overflow/artifact admission. For EACH declared region (including unused small regions), emit a nonblocking MEMORY_LOW_MARGIN warning if free < 1024 OR free * 20 < length. Equality alone does not warn. Keep integer comparisons and deterministic model-region order. Explain union free space is not largest contiguous free block, runtime stack/heap peak, or initialization proof.

Keep existing build memory and warnings list-of-string contracts. Add optional `memorySummary` to BOTH schema-1 and schema-2 identities: {basis:"elf-map-static-v1", regions:[{name,origin,length,used,free}], warnings:[{code:"MEMORY_LOW_MARGIN",region,freeBytes,lengthBytes,belowBytes,belowPercent}]}. New successful runner builds always emit the summary including empty warning arrays. Older identities without it remain valid with unchanged build IDs and typed roundtrip. Optional builder input defaults to absent for existing callers. Summary is hashed by existing compute_build_id; do not exclude it. Schema optionality allows current readers to read old receipts; old runtime may reject new fields, require matching current runtime for new receipts. No new schema version or admission relaxation. Both checked-in schema copies identical.

Strictly validate summary shape, exact integer fields (not bool), ranges, used+free==length, unique names/nonoverlapping valid address ranges, deterministic warnings exactly corresponding to region rows and threshold predicates. No unvalidated dict alias escapes: frozen typed values and fresh to_dict/from_document roundtrip. Schema validation and semantic validation must reject malformed/forged summaries even with recomputed buildId. Actual current-build admission must recompute/compare summary with validated ELF/MAP and current model when a summary exists; warning tampering must not be accepted as true measured evidence. Preserve legacy no-summary admission, schema-2 build-only restrictions and cleanup behavior.

Successful BuildReport.warnings and build-result warnings expose deterministic readable MEMORY_LOW_MARGIN strings derived from the same summary. Do not emit successful identity/summary on failed builds. CLI/MCP already propagate BuildReport; verify fields survive. No automatic rebuild, memory layout changes, ignore switches or hardware actions.
