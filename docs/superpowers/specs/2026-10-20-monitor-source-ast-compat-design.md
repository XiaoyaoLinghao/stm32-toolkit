## Frozen design and contracts

Retain the current GNU Arm GCC preprocessor and installed Clang frontend behind the existing single source adapter. This slice explicitly supersedes the earlier slice's non-goal of leaving GNU asm compatibility unresolved: add one narrow declaration-discovery compatibility policy between GCC preprocessing and Clang AST parsing. It is not a new compiler, general C parser, fallback engine, or firmware/code-generation path. The original GCC preprocessing flags/macros and conditional branches remain authoritative.

The policy may edit only an entire ordinary string-literal token whose raw bytes are exactly `"vfpcc"`, as a standalone comma-delimited clobber entry after the third top-level colon of a lexically established GNU extended-asm construct and before its fourth top-level colon or closing parenthesis. Recognize whole asm keywords and valid optional qualifiers; ignore comments, quoted tokens and preprocessor directives, and account for nested parentheses/brackets/braces. A string in any other section is not eligible. Prefixes, escapes and adjacent concatenated literals are not the exact token. If the helper cannot prove the construct/entry boundaries, do not transform it and let normal Clang validation decide the unit. Unterminated or otherwise malformed input must not cause speculative edits or acceptance.

Map the seven bytes `"vfpcc"` to the seven bytes `"cc"   ` only in the temporary `.i` used for full zero-exit Clang AST discovery. Total length, every newline, all line markers and every other byte remain identical. The mapping is solely for source declaration discovery; no generated firmware is compiled from it and no asm execution equivalence is asserted. Original source/header, project model, generated build files, ELF and firmware identity are unchanged. Keep it linear and bounded by the existing preprocessed-input/time budgets. Do not add a general token rewriter or normalize unknown clobbers.

Independent review round1 exposed physical-line-splice ambiguity and overlapping rescans. Conservatively return the entire input unchanged when raw backslash-LF, backslash-CRLF or backslash-CR occurs; GNU preprocessing already folds source splices before this stage. Never treat a splice as token-separating whitespace, including in CRLF continued comments/directives or identifiers. Consume one shared token stream without restarting or rescanning overlapping asm regions. Nested asm constructs may remain wholly unmodified when their boundaries cannot be proved by this narrow policy; no general nested-C parser is required. Regression evidence must cover CRLF comment/directive continuations, identifier splicing and deeply nested input, including structural proof of one bounded scan rather than only timing a small normal example.

One policy version is a source of truth for both the SourcePlan stage/fingerprint and engine_version. Compiler inputs, policy revision and tool versions must distinguish old partial cached results from the new parser input. Existing schemas, source coverage semantics, public reason/error codes, pagination/cursors, refresh grammar, counts and lifecycle remain unchanged. `coverage.complete` still requires all declared units to have completed zero-exit AST parsing, discovery and adoption without issues/truncation; a standalone successful compiler probe is not sufficient.

Within each `_discover` call, memoize only successful `_safe_path` results for the exact root/candidate identity; keep virtual/external-path exclusion and `_safe_path` checks unchanged. Revalidate every unique cached path at traversal completion and require the same absolute/relative result. No cross-unit, persistent or global path cache is added. Keep authoritative provider pre/post source/firmware snapshots and binding checks. Per-unit discovery is staged: validate the entire AST and all discovered functions/declarations, duplicate merges, unique entry limits, paths and deadlines before updating shared index maps and parsedUnits. Failure leaves the prior successful index unchanged, with truthful issues/truncation. Memory, byte, unit and deadline limits remain unchanged; do not silently raise them to obtain53/53.
