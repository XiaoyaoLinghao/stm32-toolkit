## 四个可运行场景

1. 观测组保存、探针操作或采样操作被明确拒绝：中文错误留在当前工作台；表格、图表、选中项、当前页和未提交草稿继续存在。用户可以查看原因、关闭提示或确认后重试原操作。
2. 目录搜索、分组列表、历史翻页和导出状态/下载失败：显示操作名称与错误，重试保留原查询、游标或任务 ID。失败不覆盖最后成功的数据；历史翻页失败不改变页栈；旧响应不能盖过新响应。
3. 写入成功而随后的读取刷新失败：报告“刷新”失败，仅重试 GET。写入请求响应不确定时不重复 POST；能核对的场景提供刷新，不能核对的导出创建说明结果未知并保留表单。
4. 初始读取普通失败：出现可重试的初始化提示，不无限加载；只有完整初始化成功才启用工作台及实时连接。真实认证/访问拒绝仍阻断并提示重新打开。

## 错误分类与恢复

`ApiFailure` 线协议保持不变。UI 以精确 code 分类，普通未知错误不能一概成为致命错误。

| 情形 | 展示与动作 |
| --- | --- |
| `MONITOR_AUTH_REQUIRED`、`MONITOR_PEER_REJECTED`、`MONITOR_HOST_REJECTED`、`MONITOR_ORIGIN_REJECTED`，以及既有启动 `MONITOR_SESSION_EXPIRED` / `MONITOR_ACCESS_REJECTED` | 阻断；停止 live 并使在途普通响应失效；使用原重新打开提示；不能以普通重试恢复权限 |
| GET/下载/本地校验的普通失败 | 工作台提示；GET/下载可重试捕获的原输入；本地无效导入要求重新选文件，不能自动发送无效数据 |
| mutation 获得明确失败 envelope | 工作台提示；“重试上次操作”先显示原操作的中文摘要并确认，然后重发不可变的原输入；原编辑按钮继续提交当前草稿 |
| mutation 的 `MONITOR_TRANSPORT_FAILED` / `MONITOR_RESPONSE_INVALID` | 写入结果未知，不提供直接重复写入；组类刷新完整组列表，探针/采样刷新状态，导出创建无查询 ID 时只能说明未知并由用户自行重新发起新操作 |
| mutation 成功后的 GET 失败 | 单独 `groups.list` 或 `status` 失败；重试只做读取，不再发送已确认成功的 mutation |

不自动重试，不加 timer/backoff，不改变 POST 幂等语义，不捏造任务 ID。刷新成功只表示完成读取，不自动声称原不确定写入成功。

## 状态、生命周期与依赖冻结

依赖方向仍是组件 → controller → API；controller 调度动作，reducer 是可见请求、错误与已接受数据的唯一来源。组件不直接调用 API。中文字符串集中于 presentation 层。

- 新增只读 scope `groups.list`；既有 scope 不改线协议。每次请求都有单调 requestId；pending、failure、retry/dismiss 均关联 scope 与 requestId。
- failure 在 UI 内扩展为带 requestId、恢复方式和原操作中文摘要的记录；wire `ApiFailure` 不扩展。恢复方式为 read-retry / write-confirm / reconcile / input / none；致命分类单独决定 blockingError。
- 不可变重试输入和执行闭包只归 controller，不放入 reducer/持久化；UI 仅调用 `retry(scope, requestId)` / `dismiss(scope, requestId)`。确认框提交前再次验证 id，过期确认不能重发新请求。
- request.started 清除同 scope 旧失败，其他 scope 不受影响。成功与失败都必须匹配最新 pending ID 后才能提交；成功清理与数据应用为一个受保护的状态转移，不能先 clear 再无条件 loaded。
- controller 同步保护在途重复动作，关闭/认证阻断后使在途回调失效。独立读取 scope 可并行；同一 mutation 家族（groups、probe、sampling、export 创建）不同时重放两个写入。界面 pending 禁用对应重复动作；双击与旧确认也须被 controller 拦住。
- 初始化的 status、probes、全部 groups 页是一个完整快照；任何失败均不发布部分初始状态。成功后仅建立一个 live；close/迟到响应不能重开 live。现有已初始化工作台内的普通失败不关闭 live。
- 组列表每次完整分页后原子提交，失败保留此前完整列表。刷新不得覆盖正在编辑的草稿；明确保存成功只能在草稿仍等于提交快照时更新对应 revision/保存结果。切换组/新建草稿保持既有明确用户动作语义。
- 目录失败保留最后成功条目和可重试游标，重试使用精确 kind/query/cursor/binding；绑定变更后的响应或重试不应用旧绑定数据。
- 历史已接受 query/page 是页导航依据；页栈只在成功页面提交后推进或回退。草稿输入不因失败消失；通用重试也必须正确更新页栈。
- 当前导出 artifact 的原提交范围及格式由 reducer 的 exports 状态保存，创建成功时由捕获输入附带提交；轮询同 ID 保留，新的创建替换。组件不根据当前表单或当前历史查询猜测任务范围。导出 pending/忙碌在每次完成（含失败）后释放，通用重试也受 pending 保护。
- 原有导入文件读取代次及确认保护继续保留。POST 失败的原导入文档由 controller 重试快照持有，页面关闭预览不会丢掉恢复输入。

### 第一轮完整差异审查澄清

以下是既定错误生命周期在交错操作中的明确规则，仍属于同一 UI02 切片：

- 目录绑定或当前导出任务变化时，旧上下文的读取失败必须失效；可以在上下文变化或尝试重试时原子清除旧记录，不能留下点击后无效果的可用重试按钮。迟到的旧上下文失败也不能重建记录。旧导出下载仍可按捕获任务 ID 执行，不把下载与当前任务状态刷新混为一谈。
- 目录只接受尚未应用的下一页游标。已经应用的同一页再次完成不能重复追加，即使组件状态尚未刷新、两次请求没有时间重叠。旧 catalog.requested 内部动作不构成兼容义务，不得为旧测试保留破坏已接受数据的路径。
- 探针/采样重试同时捕获原上下文。确认摘要含原探针 ID，采样含原组和 run；重试前核对 workspace/session/project、probe 与 binding epoch，采样再核对 run/group。零参数后端方法也不能隐式操作新目标；上下文已变则废弃旧重试，绝不发出 POST。已有明确目标参数原样保留，不扩展 wire。
- 初始化仍并行读取并原子发布完整快照，但任一普通失败应立即结束可见 pending 并允许手动重试，不能等待另一悬挂读取。完整成功与已观察到的失败竞争；同一最新初始化尝试、同一 controller 生命周期的迟到致命错误仍可建立阻断。新的尝试或 close 使旧尝试全部观察者失效。不新增超时、自动重试或 API 取消协议。
- 已确认 mutation 返回的 WatchGroup 可以直接 upsert 到已接受组列表，保持新选中 ID 可解析；这属于权威写入回执，不是发布部分 GET 页。只有原提交草稿仍在编辑时才改变选中项/草稿身份，之后完整 GET 失败仍不能截断已有列表。正在编辑或已切换的其他草稿继续保留。

## 工作台呈现

导航下方增加浅色“操作提示”区域，按独立失败记录呈现全部未处理错误，包含操作名称、中文原因、适用恢复动作、关闭按钮和折叠诊断详情。错误不会被 `??` 优先级或折叠面板隐藏。普通提示不替换工作台，不重置 tab/编辑器。列表、图表等保留最后成功数据，不将旧数据冒充本次成功。

写入重试确认需展示原目标和输入摘要：组名/ID、导入数量、探针 ID、采样目标或导出格式和范围。拒绝/关闭确认不发送请求。读取重试不要求额外确认。可访问名称和忙碌状态使用中文。
