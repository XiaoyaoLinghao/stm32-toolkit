## Public behavior

Optional Schema 2/3 `generation.linkerFragment` is a portable project-relative path to a user-owned UTF-8 GNU-style section fragment, for example `linker/user.ld`. Configuration reads it, validates a deliberately bounded grammar, and renders its normalized sections inside managed `linker/stm32tk.ld`. The exact raw fragment bytes are identity inputs. The user never edits the managed linker or generated-files digest. Omission preserves old model hashes and generated output. Empty/non-string paths are invalid. Combining with `nativeLinkerScript` is refused; a native script retains its separate existing ownership route.

Initial grammar is custom writable-RAM NOLOAD output sections only, up to 32 sections and 64 KiB raw bytes. Each section uses `.name [integer-address] (NOLOAD) : { statements } > REGION`. ASCII section identifiers are bounded; decimal/hex addresses are exact uint32 values. Statements may be `. = ALIGN(n);` (positive power of two, at most 4096), `*(selectors)` or `KEEP(*(selectors))`. Selectors are exact custom section names or their trailing `.*` suffixes; no file selection, arbitrary wildcard, expressions, symbol assignment, data emission or includes. Require at least one selector per section, bound total statements/selectors, reject duplicate/overlapping selectors and case-colliding output names. C block comments and whitespace may be accepted, but never interpreted as directives. Fully consume the input; malformed/trailing syntax fails closed. Empty/comment-only fragments are rejected.

Reject managed/reserved section families (vector/text/rodata/data/bss, constructors/ARM unwind, heap/stack, fixed `.stm32tk.abs` and standard GNU metadata), including names/patterns consumed by existing template wildcards. Selectors must belong to their own custom output family (`.sram2`/`.sram2.*` for `.sram2`), so they cannot steal managed or another custom section. No MEMORY/SECTIONS wrapper, INPUT/GROUP/SEARCH_DIR/INCLUDE, ENTRY, AT, PHDRS, INSERT, /DISCARD/, macro expansion or external file access. This is an explicit supported subset, not an arbitrary GNU linker-script interpreter. Unsupported syntax gets field/path/rule and actionable remediation; do not suggest patching managed hashes.

Region names must resolve exactly to the same canonical model map used by fixedSections, linker, ELF and MAP. Only writable regions are accepted. No new regions or inferred capacities. Explicit addresses must start within the chosen region; linker and actual ELF/MAP validation verify final sizes and overlaps. For projects with a fragment, validate each materialized nonempty fragment section against its selected region, explicit address if given, SHF_ALLOC/SHT_NOBITS attributes, and reject overlap among nonempty allocated ELF sections (including fixedSections, managed heap/stack/data/bss). A selector that matches no input may legitimately produce no output section. Existing MAP union accounting is not proof of non-overlap. Render fragment sections after existing fixed sections and before managed data/bss, in deterministic source order. No changes to fixedSections semantics, startup initialization, programming eligibility or controller setup. NOLOAD sections are not automatically copied or zeroed; initialized C objects must not rely on initializers in these sections. External RAM must already be usable before access.

## Ownership and freshness

Reject absolute/traversal/unsupported paths, missing/directory/oversize/non-UTF-8 files, redirection at any path component (symlink/reparse), and collisions with generated targets or other declared inputs. Keep the file user-owned and unchanged. Configuration plan binds path plus exact byte SHA and rendered output; apply revalidates before writes, preserving existing transaction and user-drift guards. Parse/render from the same bounded bytes, and cross-check reads against the frozen evidence to refuse races.

Build must not silently use an old merged linker after fragment edits. The fragment path/content participate in model identity, generated configuration provenance and build input snapshots. An edit (even a comment), removal or path change invalidates old configuration/build evidence. Refuse before compiler spawn with structured remediation to rerun project configure PLAN/APPLY and then build `--clean` when required. Handle removing the option too; do not gate stale checking solely on the current manifest field. Existing generated linker/manifest validation remains mandatory. Link dependency tracking must ensure a regenerated merged linker causes relinking (including direct CMake use); add conditional LINK_DEPENDS for the fragment route without changing old no-option bytes. Direct CMake alone does not parse changed fragments: users reconfigure through Toolkit first.

No new MCP tool or migration parameter is needed: edit the reviewed manifest/fragment, then use existing `stm32_project_configure` PLAN/APPLY and build. VS Code guide and migrate-keil skill must show exact existing CLI/MCP parameters/response fields, truthful installed-runtime availability, error remediation, and the distinction from fixedSections/memory.layout/nativeLinkerScript. No global skill or installed runtime edits.
