## One operation and one process boundary

Write only `docs/codex/returns/SESSION-TRACE/session_trace.py` and
`tools/stm32-toolkit/tests/test_session_trace.py`.
The script is run-specific/non-packaged. Default invocation refuses before
filesystem/runtime/registry/process activity. A prepared explicit execution flag
is not user authorization and must not be executed against hardware in this slice.

Use one direct `subprocess.Popen` child with the same verified interpreter,
`-B`, and the same saved helper source. No multiprocessing, Python-object
pickling, general module/factory loader, shell, command string or alternate
interpreter. Do not create a generic service/framework. Keep the parent stdlib-only;
reuse existing Toolkit selector/default driver and lease API in the child.
Private test-only launcher/backend injection must not be exposed as a CLI capability.

Environment switches inherited by the ordinary saved helper are a CLI capability
too. Keep fake backends, modes and test receipt paths in the test module. A fixed
test bootstrap may import this exact helper and explicitly inject a Python-only
launcher/backend, then exercise its unchanged `main` chain. No production argument,
environment or request file selects it. Verify the production launch argv/source/
interpreter separately; this adds no public extension or module loader.

Parent exclusive-creates one output directory and attempt record. Fixed run-owned
files carry a small closed request, child READY, parent GO, child result, events
and private native traceback. Correlate them by fresh attempt/session identity
and the exact request digest. Reject reuse/stale/wrong/extra data; read bounded
files and wait finitely for an incomplete in-progress JSON write. No command or
import string is accepted from these files. Request may contain the already-public
probe selector, never a raw hardware serial; results retain its fingerprint.

Child reserves its one-shot output before backend work, uses its real process
identity to acquire the exact-probe OBSERVE lease in the explicit original shared
data root, and publishes READY bound to its actual PID/source/request/lease.
Use `ProbeLeaseManager` and its real loopback-only health contract. No fallback
registry, fake owner/health success, handoff ticket or takeover. Lease/health
software work before GO performs no device enumeration or USB access.

Parent writes GO only after the Popen handle was returned, READY matches that
exact PID/source/request, and the original absolute deadline has not expired.
A creation failure, unknown startup, cancellation or bad READY never writes GO.
Thus even an uncertain partial process creation cannot authorize USB. The child
waits finitely for its matching GO, then performs exactly one lazy driver
acquisition, one existing exact-selector enumeration/selection and one normal
default-driver Session construction. Use the original selected probe object.

Session options match accepted normal programming:100000Hz, SWD,
auto_unlock=false, connect_mode=halt, no_config=true,
pack.debug_sequences.enable=true, primary_core=0, explicit absolute project_dir
and target_override, resume_on_disconnect=false, user_script=os.devnull;

Close a returned Session through its existing close path once; do not compensate
for a failed constructor with extra probe operations.

## Lifetime, trace and truthful outcomes

One absolute parent deadline covers startup, READY/GO and child work: default20s,
maximum30s, plus at most2s owned termination join. If a known-live child needs
cleanup, request its termination once and wait boundedly. No retry, second child,
kill fallback, unrelated PID operation or process discovery. If startup has no
usable handle, report UNKNOWN and never grant. If a child survives, retain
UNKNOWN and its live child-owned lease; parent never releases that lease.
Do not use a Popen context manager/communicate/unbounded wait that waits on a live
child at exit. A normal CLI return or exception must not implicitly join or
terminate a child. No global atexit or interpreter changes or library-caller exit.

Record PID/exit/alive evidence before releasing proven-terminal owned handles.
On pinned Windows CPython, release actual process/pipe handles after known exit,
not merely the Python reference, and verify real temporary-registry reuse. Never
close a live/unknown handle to imply termination. Startup, cleanup or handle-close
failure must fail the overall diagnostic. Preserve the initiating failure and
cleanup separately, including cancellation. Avoid silencing file-write failures.

Arm exactly one actual `faulthandler.dump_traceback_later` immediately before
Session construction (default1s, repeat=false, exit=false); cancel on return/error
before closing its run-owned file. Arm failure prevents construction; cancel
failure is visible, does not silently close an active writer and cannot become
success. Capture bounded fixed stage/elapsed markers without raw exception values,
USB packets, registers, locals or credentials. The private stack contains only
file/function/line frames and is not a public API field.

Physical target state is always UNKNOWN. Own-operation facts (constructed,
Session closed, no Session.open) are separate. A returned constructor is narrow
evidence; overall success also requires confirmed child exit0, close/snapshot/lease
cleanup success, matching bounded result and no parent/lifecycle/handle failure.
Matching GO includes the child's acquired leaseId, finite timing and unexpired
original budget; a completed matching claim precedes GO. Refuse stale/extra
one-shot outputs before backend access. Recheck known cancellation at the grant
decision and preserve launch-time cancellation/parent exceptions separately from
cleanup. Persistence/snapshot errors fail returned and printed success consistently.
Neither a selected100kHz policy nor constructor success proves attachment,
programming, clock rate, application execution or a repaired physical fault.
