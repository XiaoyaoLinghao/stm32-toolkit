## 5. Security, privacy, performance, accessibility, and compatibility

- Security checks (all automated, all pass):
  - No shell, no command strings anywhere in the process layer (`shell=False`, argv tuples only; verified by tests); stdout/stderr drained concurrently with hard byte (1 MiB) and line (20,000) caps, exact line-cap cutting at the Nth newline, overflow flags, and continued draining to EOF so a chatty child can never deadlock the caller.
  - Timeout 1..3600 validated at both `ProcessRequest` and `BuildRequest`; on timeout the whole child tree is terminated (POSIX: new session + `killpg` SIGTERM → 2 s grace → SIGKILL; Windows: `CREATE_NEW_PROCESS_GROUP` + `taskkill /PID /T /F` with direct terminate/kill fallback), then reaped with a bounded wait.
  - Stale-output defense: `run_build` never trusts toolchain exit 0 — the current ELF and MAP files are re-checked (existence, bounded size, SHA-256) and re-validated (ELF32 LE ARM, `.isr_vector`, `Reset_Handler`, entry-point consistency, undefined non-weak symbols; MAP `Memory Configuration` + output-section rows with anchored regexes, interval-union region usage, overlapping-region rejection) before any publication.
  - Atomic evidence publication: `build.log` → `firmware-identity.json` → `build-result.json`, each written via sibling temp + flush + `fsync` + `os.replace` + directory fsync (POSIX); the result file is the freshness commit point — a schema failure publishes nothing, a write failure retains only the log, and context freshness requires the complete chain.
  - Evidence-chain freshness: `elfFresh` requires result `status == "success"` and `preset` matching its directory, result↔identity `buildId` link, `schemaVersion == 1`, current Git HEAD equal to `gitHead`, identity elf/map paths equal to the model paths, current input-snapshot digest equal, and current ELF/MAP size+SHA-256 equal to the identity digests; every missing/malformed/tampered element fails closed to `False`. mtimes are never consulted.
  - Bounded reads everywhere: 8 MiB/file + 64 MiB aggregate snapshot, 64 MiB ELF/MAP artifacts, 8 MiB evidence JSON, 64 KiB read chunks; fail-closed `BuildError` rules; portable relative paths only in details (no absolute paths, no exception text, no environment/source bytes).
  - Lock: `.stm32-toolkit/build.lock` advisory non-blocking exclusive lock (`flock` POSIX / `msvcrt.locking` Windows), released by close; contention → `BUILD_BUSY`; lock-open/lock-fd failures → `BUILD_ENVIRONMENT_ERROR`.
  - Schema validation of the identity document against the packaged schema before publication; root and packaged schema copies byte-identical and verified in an installed wheel.
- Privacy/redaction checks: every `OperationResult` failure `details` contains only stable rules/portable relative paths/stage/preset/returncode; identity evidence paths are project-relative with `/`; no credentials, host paths, environment values, or stack text; the report contains no self-referential SHA.
- Performance measurements (§5; `time.perf_counter`, 3 warm-ups then 20 runs, min/median/max): input snapshot (200 declared sources) **8.0 / 8.1 / 8.3 ms** (budget 500); MAP (5,000 sections) + ELF validation + identity construction **24.4 / 24.7 / 33.6 ms** (budget 500) on Linux 7.0.0-22-generic x86_64, CPython 3.10.11. No timing assertions in the test suite.
- Accessibility/input checks: `NOT_APPLICABLE` for UI; stable English messages with structured `details`.
- Compatibility checks: CPython 3.10+ (verified on 3.10.11); UTF-8 with replacement decoding (never platform default); portable `/` paths in all evidence; Windows branches simulated on Linux via module switches and covered by tests; real Windows process-group/lock and real ARM toolchain builds are Codex gates; the 17 suite skips are pre-existing Windows-only platform skips.
