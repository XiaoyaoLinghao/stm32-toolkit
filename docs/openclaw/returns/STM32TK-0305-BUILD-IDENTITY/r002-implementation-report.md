## 5. Security, privacy, performance, accessibility, and compatibility

- Security checks (all automated, all pass):
  - No shell, no command strings: `run_process` uses `Popen(args=tuple, shell=False)` only; the runner constructs exactly `("cmake", "--preset", preset)` and `("cmake", "--build", "--preset", preset[, "--clean-first"])`; Git evidence uses exactly `git rev-parse --verify HEAD` and `git status --porcelain=v1 -z --untracked-files=all`; argv recorded in logs as JSON arrays; PATH resolution never persisted in results.
  - Bounded everywhere: 1 MiB + 20,000 lines per process stream with overflow drained to EOF (no deadlock, deterministic truncation flags); 8 MiB per input file, 10,000 files, 256 MiB aggregate snapshot; 64 MiB ELF / 32 MiB MAP / 8 MiB evidence reads with `limit + 1` reads; timeout 1..3600 at both request layers; on timeout only this invocation's tree is terminated (POSIX new session + `killpg` SIGTERM→2 s→SIGKILL; Windows `CREATE_NEW_PROCESS_GROUP` + graceful signal→2 s→bounded `taskkill /T` with `kill()` fallback) and reaped.
  - Fail-closed path handling: every consumed/published path is portable (NUL, drive, UNC, absolute, `.`/`..`, empty components, mixed separators rejected), resolve-contained, regular-file-checked; escaping symlinks/junctions and loops rejected; declared sources/includes can never point into `build/` or `artifacts/migration`.
  - Stale-output defense: exit 0 is never trusted; success requires current valid ELF/MAP and either changed output metadata during the invocation or a matching prior success record/identity (exact input snapshot, Git HEAD, target, preset, ELF/MAP digests); missing/unchanged outputs fail closed; failed builds publish a failure record that supersedes any older success for context freshness.
  - MAP/ELF fail-closed: region rows must exactly equal the model regions in order; duplicate/malformed/overflowing/overlapping/ambiguous rows rejected; out-of-region intervals rejected (never clipped); VMA+LMA interval-union accounting with reachable overflow codes; ELF32 LE ARM only, `.isr_vector` ≥ 8 bytes in an executable region, defined `Reset_Handler`, Thumb-consistent entry, second vector word match, undefined non-weak symbols rejected, `SHF_ALLOC` containment, fixed `.stm32tk.abs.<ADDR8>` addresses verified; hashes taken only after validation.
  - Atomic evidence: temp + flush + fsync + `os.replace` + directory fsync; log → identity → result order with the result as the commit point; failure never rewrites the identity sidecar; publication failures return `BUILD_EVIDENCE_FAILED` and clean up only this invocation's temporaries.
  - Lock: nonblocking advisory `.stm32-toolkit/build.lock` (real `fcntl`/`msvcrt` per host behind the product abstraction), `BUILD_BUSY` on contention, released on every exit, never deleted/broken for another holder, stale unlocked file never blocks.
  - Context: `elfFresh=True` only when the complete chain validates — success record, packaged-schema identity with independently recomputed `buildId`, record↔identity agreement, current Git HEAD/target/preset/input snapshot/ELF/MAP digests, contained regular paths; no mtimes, no other-preset search.
- Privacy/redaction checks: details and `to_dict()` never contain host exception text, absolute/temp paths, process output, source bytes, environment values, usernames, or credentials; the `log` detail is the portable published-log path; the published log normalizes LF and replaces every canonical project-root spelling with `<PROJECT_ROOT>`; JSON is UTF-8 without BOM, `indent=2`, `ensure_ascii=False`, one final LF; the report contains no self-referential SHA and no moving commit totals.
