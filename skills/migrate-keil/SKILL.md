# Migrate Keil Project

## Workflow

1. **Context first.** Call `stm32_project_context` (no arguments). Read `capabilityDetails`, not only the legacy booleans: `status=available` means the entry point applies to this project, `blocked` means a named prerequisite is missing, and `not-evaluated` means context did not check it. `hardwareDiscovery=not-performed` means no probe was queried. Context never scans all sources or proves migration readiness.
2. **Select and inspect.** Use `data.project.files` to identify the project-root-relative `.uvprojx` (context does not list target names). For multiple project candidates, ask the user to choose one. If the exact target is unknown, call `stm32_keil_inspect(uvprojx="<selected relative path>", includeBaseline=true)` and omit `targetName`; on `KEIL_TARGET_SELECTION_REQUIRED`, present `details.targets` and let the user choose, then inspect again with that exact `targetName`. A successful result carries `data.inspection.target_name`; preserve that exact value, plus the same `uvprojx`, for every later call. Never guess a target. `baseline.available` only means a historical AXF or MAP was found and parsed; it does not prove a current build, toolchain, source identity, or authorized baseline.
3. **Preflight without Git.** Call `stm32_keil_preflight(uvprojx="<same path>", targetName="<same target>")`. Preflight is read-only, requires no Git, and returns typed `analysis.blockers` separately from `planReadiness` (prerequisites for obtaining a plan) and `applyReadiness` (always false pending a reviewed, authorized plan). A successful call means analysis completed; it does **not** mean the project is ready to apply and never returns an applicable plan ID. Report every blocker and every unmet prerequisite, including whether the repository, committed HEAD, toplevel, or clean worktree is missing.
4. **Optional CMSIS startup review.** A conventional ST/CMSIS Cortex-M ARMCC startup is supported only through the explicit opt-in `startupStrategy="generate-cmsis-gcc"` (CLI `--startup-strategy generate-cmsis-gcc`). Add `startupSource="<exact project-relative included ARMCC .s path>"` (CLI `--startup-source`) whenever more than one included non-empty assembly source exists; omitting it then returns `MIGRATION_STARTUP_SELECTION_REQUIRED` with `details.candidates`. Omit both options to retain the existing `ARMCC_ASSEMBLY_UNSUPPORTED` blockers. The same two values must be passed to preflight, convert and apply; they are bound into the plan digest and apply replans with them, so a caller-edited or omitted choice returns `PLAN_CHANGED`. The managed destination is `Startup/stm32tk_startup_gcc.S`; the original ARMCC startup is never modified or deleted. Review `analysis.startup` (source path/hash, ordered vector entries and reserved slots, stack/heap bytes, reset pattern, generated path/digest, warnings, diagnostics). Supported sources are normalized cortex-m3, cortex-m4 and cortex-m7 conventional files; unknown instructions, custom reset/handler code, multiple vector tables, vector expressions, unsupported cores/layouts and undeclared handlers remain blockers. The generated GCC runtime is not ARMCC, ABI or Microlib behavioral equivalence, and a `MIGRATION_STARTUP_TARGET_COLLISION` is never overwritten.
5. **Resolve blockers, not rules.** Report encoding, assembly, scoped compiler option, scatter/memory, and manifest conflicts with their portable paths and safe next steps. Toolkit never silently transcodes non-UTF-8 input, blindly replaces ARMCC startup code, edits a conflicting manifest, deletes untracked files, or weakens a rule to make preflight pass. The startup opt-in above does not translate arbitrary assembly: unrelated `.s` files remain `ARMCC_ASSEMBLY_UNSUPPORTED`. For a source-encoding blocker, the supported preparation route is the separate `normalize-source-comments` companion skill: it previews explicitly declared per-file charsets and copies only reviewed comment-only UTF-8 files to a new external directory. It never edits the original project, guesses a charset, or resolves startup, scoped-option, scatter/memory, Git/apply, or baseline blockers.
6. **Git is an owner decision.** A missing Git repository, unborn HEAD, or dirty/untracked work blocks only planning/apply, not analysis. Explain the exact prerequisite and let the project owner decide whether to establish a clean committed baseline. Never run `git init`, commit, stash, clean, or rewrite Git state on the user's behalf.
7. **Read-only plan.** Only after preflight has no blockers and `planReadiness.ready` is true, call `stm32_keil_convert(uvprojx="<same path>", targetName="<same target>", startupStrategy="<same value or omitted>", startupSource="<same value or omitted>")` with no `planId` and no `authorized`. This returns the deterministic, Git-bound `keil-conversion-plan` (a PLAN response). Show its `data.plan_id`, every blocker, `data.startup` when present, and the exact changed paths and diffs from `data.patches[].unified_diff`. For the startup route, verify that only the selected ARMCC source is replaced in `build.assemblySources`, that `Startup/stm32tk_startup_gcc.S` is the only generated assembly patch, and that `memory.stackSize`/`memory.heapSize` plus `generation.runtimeInitialization="cmsis-gcc-v1"` match the evidence.
8. **Stop on blockers.** If `data.blockers` is non-empty, report them and stop; never apply a blocked plan.
9. **Authorize.** Ask the user for explicit authorization for the exact displayed `data.plan_id`. Never infer consent from inspection, preflight, or the earlier read-only plan call.
10. **Apply.** Only after the user authorizes, call `stm32_keil_convert(uvprojx="<same path>", targetName="<same target>", startupStrategy="<same value or omitted>", startupSource="<same value or omitted>", planId="<exact data.plan_id>", authorized=true)`. The PLAN response field is `data.plan_id`; the APPLY request argument is `planId`. The core replans with the request startup options and rechecks the digest, Git, input-drift, and authorization guards before its first write. If the startup evidence, destination collision state or options differ, it returns `PLAN_CHANGED` or a stable `MIGRATION_*` failure and writes nothing.
11. **Return the result.** Report the `keil-conversion-apply` result: the conversion report path, the schema-3 `.stm32-project.json` path, patched source paths, created paths (including `Startup/stm32tk_startup_gcc.S` when generated), and any warnings. If the result is a failure (`AUTHORIZATION_REQUIRED`, `PLAN_CHANGED`, `MIGRATION_*`), report the exact code and details and stop. After apply, configure and build through their own read-only plan and explicit authorization steps.

## Rules

- `stm32_keil_inspect`, `stm32_keil_preflight`, and the plan call are read-only; verify the plan before any mutation.
- Capability or entry-point availability does not establish migration readiness. Only the current preflight/plan evidence does.
- Within this migration workflow, the apply call is the only project mutation. Pass exactly the reviewed `data.plan_id` as the APPLY request's `planId`, with the exact same project/target selection and the exact same `startupStrategy`/`startupSource` values (or both omitted). The separate `normalize-source-comments` helper may write new converted copies outside the project after explicit review; it is not a migration apply and never edits originals.
- The startup route is a bounded, reviewed adaptation: it accepts only the conventional Cortex-M3/M4/M7 CMSIS grammar and never executes or copies unknown ARMCC logic. Do not advertise arbitrary ARMASM translation, do not claim ARMCC/Microlib binary or ABI equivalence, and do not treat generated vectors or runtime initialization as hardware-qualified.
- Review `data.startup.diagnostics` and warnings before authorizing. A destination collision, unsupported core/grammar, size-bound failure or changed option set is a stop condition, not a reason to overwrite files or edit the plan.
- Do not parse `.uvprojx` XML, rewrite project source files, render templates, or run compilers yourself. The companion helper's copy-only external output is not a project rewrite.
- Never claim success; report the returned `OperationResult` exactly as received and finish immediately.
